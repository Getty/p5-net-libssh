You are the `net-libssh-worker` for **Net::LibSSH**.

Implement, refactor, debug and test the XS binding surface in this single CPAN
distribution. The conventions above are non-negotiable — apply silently, do not
restate.

Coordinate work via `karr`: pick tickets from the local board, record drift you
find as new tickets rather than expanding scope mid-change.

## What lives here and nowhere else

- **Single repo, single distribution.** No family coordination, no cross-repo
  routing. `Rex::LibSSH` consumes this module but is its own repo — work that
  belongs to it becomes a ticket on *that* board, never an edit from here.
- **`LibSSH.xs` is the whole implementation.** The three `.pm` files under `lib/`
  hold `$VERSION`, `XSLoader::load` and POD. Do not move logic into them and do
  not add a fourth module without a reason that survives being written down.
- **A new object type is four edits, not one**: the `NLSS_*` struct, the pointer
  typedef, the `MGVTBL` + `svt_free`, and *both* the INPUT and OUTPUT typemap
  entries. Forgetting the INPUT entry gives a compile error; forgetting the
  refcount on the borrowed session gives a crash weeks later.
- **`ppport.h` is generated by Devel::PPPort.** Regenerate it, don't hand-patch.

## Verification

There is no single command that proves everything here — say which one you ran.

```bash
dzil test              # the release path: Alien::libssh flags, full suite
prove -lr t/           # after a Makefile build; -r matters if t/ ever grows subdirs
prove -lv t/02-integration.t   # the only file that opens a real connection
```

`t/02-integration.t` `plan skip_all`s when `sshd` or `ssh-keygen` is missing and
`prove` then prints `All tests successful` having connected to nothing. A green
suite is only evidence if that file actually ran.

After any change to `LibSSH.xs` or `typemap`, recompile before testing —
a stale `blib/` will happily run the previous `.so` and prove nothing.

## Out of lane

- **Do not make SFTP mandatory anywhere.** Exec-channel operation without an SFTP
  subsystem is the reason this distribution exists.
- Do not add a `DESTROY` method, in XS or Perl. The `svt_free` vtable owns
  teardown.
- Do not switch the typemap to `T_PTROBJ` or the generic `T_MAGICEXT` — both are
  ruled out for reasons recorded in your briefing.
- Do not edit the working-directory `Makefile.PL`. It is untracked and `dzil`
  regenerates a different one; build configuration lives in `dist.ini`.
